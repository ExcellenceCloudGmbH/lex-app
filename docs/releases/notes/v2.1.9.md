**No user-facing changes in this release.** It is entirely release-tooling work.

## Internal

- **Release notes now describe the frontend, not just the backend.** The interface ships as a compiled bundle with no record of which source revision produced it, so notes could only ever describe backend work. A build now records its own revision as it copies the bundle in, a check rejects a bundle whose record is missing or malformed, and the notes resolve the interface changes between two releases from those records.
- **The interface shipped in earlier releases has been identified retrospectively.** The three bundles that predate this mechanism were matched to their source revisions by rebuilding each candidate and comparing the compiled output, which is content-addressed — so the match is proven rather than inferred, and each record says which it is.
- **A release can no longer lose that information silently.** Where the interface revision genuinely cannot be determined, the changelog says so in as many words instead of omitting the section — which previously looked identical to a release with no interface changes. A repair command finds those and fills them in later.
- Nothing in this pipeline can hold up a release: every failure path ships the release and records what it could not determine.

**No frontend changes in this release.** The interface is unchanged from `v2.1.4`.
