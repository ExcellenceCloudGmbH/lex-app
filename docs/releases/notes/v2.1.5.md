## Bug fixes

- **Calculations no longer crash part-way through on a date comparison.** The move to timezone-aware timestamps in `v2.1.4` left a seam: a date read from the database carried a timezone, while one built in memory — loaded from a spreadsheet, set in code, or read from a fixture — did not, until it next made a round trip. Comparing the two, which happens naturally when a single column of a table is fed from both, aborted the calculation. Datetime values are now given a timezone the moment they are set, using the same interpretation the database applies on save, so the stored instant is unchanged.

- **Spreadsheet writes no longer fail on timezone-aware dates.** A second seam from the same change: the spreadsheet writer rejects a date carrying a timezone outright. Dates are converted to a plain wall-clock before writing.

**No frontend changes in this release.** The interface is unchanged from `v2.1.4`.

---

**Upgrade note:** no migrations and no configuration changes. If you have not yet read the `v2.1.4` upgrade note, do that first — this release completes that work but does not replace the data repair it describes.
