# Known Bugs Tracker
> **Back to:** [Progress & Organization](progress.md) | [Test Plan Index](index.md)
> **Audience:** Engineers triaging failing or `@expectedFailure`-marked tests.
>
> Bugs discovered by the new test suite. Each has at least one corresponding test marked
> `@unittest.expectedFailure` (live regression gate) or `@unittest.skip` (with reason) so a
> regression can never silently flip back to "green".
>
> **Workflow:** when a test surfaces broken framework behaviour, write the test asserting the
> *correct* behaviour (from docs / intent), mark it `@unittest.expectedFailure`, and add the
> entry below with a one-line description, severity, the cluster + test it lives in, and status.
> When the framework is fixed, drop the marker — the test should now pass naturally.

| BUG-022 | **Stale source-comment in `on_history_saved__chain_valid_to` claimed the L2 layer collapses `valid_to`-refinement saves into an in-place update.** Surfaced when the 5k probe was fixed in Session 53 — `test_5_82` ran for the first time and saw 5 L2 rows for 3 saves instead of the comment-promised 3. After tracing the data flow (Session 53b discussion): the 5-row outcome is **correct system-time semantics**, not a bug. Each closing of a previous L1 row's `valid_to` is itself a save() against that L1 row, and the L2 layer's job is to record "what did the system know at instant T?" — so the system genuinely needs separate L2 rows for the open-ended view (before the chaining save) and the closed view (after). Without the extra rows, system-time `?as_of=...` queries lose fidelity. The never-wired `_strict_chaining_update` flag was an aspiration that would have *broken* system-time correctness if it had shipped. Fix landed: source comment rewritten to match the real contract; `test_5_82` rewritten to assert `2N − 1` L2 rows (3 saves → 5 rows) plus a contiguous `sys_to → sys_from` chain across all five — promoted from `@expectedFailure` to a live regression gate. | Low (docs only) | 5 (5k) | `test_5_82` | **Resolved** (Session 53b — docs+test fix; no framework code change needed; the framework was already correct) |
