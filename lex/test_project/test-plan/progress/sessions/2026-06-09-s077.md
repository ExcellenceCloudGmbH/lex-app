**Sub-clusters 6p + 10m landed — calculation-log memory crash (backend OOM on opening the log panel).** Reported from the cluster: opening a calculation's log in the frontend spiked backend pod memory and triggered an OOM restart. The log view streams new lines over the WebSocket **and** backfills prior lines from a server-side buffer. **Root cause (two compounding offenders, both on the backfill path):** (1) `CacheManager.store_message` (`lex/audit_logging/utils/CacheManager.py`) did an unbounded `get`+concat+`set` of a single ever-growing string on **every** log line — O(N²) bandwidth and several multi-MB copies of the blob alive at once, with no size cap (and the documented one-week TTL was never even passed to `cache.set`). `add_table`/`add_dataframe` payloads make each line large. (2) `InitCalculationLogs` returns that whole blob in one shot, and `CalculationLogTreeView` ran `CalculationLog.objects.all()` (or every row for a calc) with a per-node child query (N+1) in `CalculationLogTreeSerializer`. **Fix:** (A) bound the cache backfill buffer to a ~256 KB tail (`MAX_CACHE_MESSAGE_CHARS`), trimming the oldest lines on write and re-aligning to a clean line boundary so the head is never a fragment; apply `CACHE_TIMEOUT` on `set`. The full log remains in `CalculationLog.calculation_log` and new lines keep streaming, so only the in-cache *recent-history* backfill is bounded. (B) `CalculationLogTreeView` gained limit/offset pagination (`DEFAULT_LIMIT=1000`, `MAX_LIMIT=5000`) with a `pagination` block + `has_more`, and resolves all child ids for the page in a single query passed via serializer context; `get_isRoot` now reads `parent_log_id` instead of lazy-loading the parent row. **Cluster 6p** (next-free after 6o; 6.109 after cluster max 6.108): 6.109 buffer never exceeds cap, 6.110 trim starts on clean line boundary, 6.111 newest retained/oldest dropped, 6.112 under-cap untouched, 6.113 set uses configured TTL. **Cluster 10m** (next-free after 10l; 10.61 placed past the 10.60 reserved-range ceiling): 10.61 default limit bounds the page, 10.62 offset walks the dataset, 10.63 child ids resolved per parent, 10.64 isRoot only for parentless rows, **10.65 the integration surface** — child queries stay constant (`assertNumQueries(3)`) across many parents (N+1 gone), 10.66 calculation_id filter scopes rows. Source files: `lex/audit_logging/utils/CacheManager.py`, `lex/api/views/model_entries/CalculationLogTreeView.py`, `lex/api/views/model_entries/serializers/CalculationLogTreeSerializer.py`.
