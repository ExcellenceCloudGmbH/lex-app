**Showcase report upgraded to customer-grade HTML + PDF + SendGrid email.** Scoping shift: the markdown step-summary from Session 25 was a fine engineer view but it isn't what a business user / customer reads — they read inboxes. This session built a proper customer-facing artefact pipeline and wired it in. New `build_showcase_report.py` renders a **branded, single-page Platform Health Report** — deep-navy header band, coloured verdict panel (green ✓ / red ✗), one card per capability with plain-English "what this proves" / "what it means if broken" paragraphs, runtime per test, a "what we test and why" glossary, and a traceability footer (build id / branch / run link). The HTML is 1998-style table-layout with inline CSS so it renders identically in Gmail, Outlook and Apple Mail; the same HTML is rendered to PDF via **WeasyPrint** (`libpango-1.0-0` + `libpangoft2-1.0-0` added to the CI apt step alongside the existing `libcairo2-dev` — pango is the only new system dep). New `send_showcase_email.py` uses the SendGrid SDK to send the HTML body with the PDF attached as `platform-health-report-<date>.pdf`; subject line adapts to the verdict (`[✓ all green]` / `[✗ action required]`); gracefully no-ops (exit 0 with a clear log line) when any of `SENDGRID_API_KEY` / `SHOWCASE_REPORT_RECIPIENTS` / `SHOWCASE_REPORT_FROM` is missing, so the pipeline can ship before the secrets land without failing the workflow. Workflow rewritten: per-test duration captured via `date +%s.%N` bookends (`awk` computes the diff, written to `$GITHUB_OUTPUT`) so the report can show "Runtime: 450 ms" per card; `actions/upload-artifact@v4` uploads both `report.html` + `report.pdf` as the `platform-health-report` artefact; the engineer `showcase_summary.py` step is kept but reverted to file-only output (removed the stdout echo + banner from session 25's last turn — the user's explicit ask was to keep the step log quiet and push the real output to the report). Brand defaults to `"LEX Platform"` but is overrideable via a `SHOWCASE_BRAND` repo variable. Stakeholder doc at `docs/ci-cd/showcase-ci.md` rewritten to describe the new flow (HTML email + PDF attachment + run artefact) and list required secrets. Local verification: HTML renders with correctly-nested quotes (one CSS quoting bug surfaced on first render — multi-word font names wrapped in `"..."` broke the outer `style="..."` attribute; switched to single-quote font names throughout); WeasyPrint installs cleanly on local (PDF 1.7, ~14 KB); email script dry-run with no secrets prints `"Skipping email: missing required env vars: SENDGRID_API_KEY, SHOWCASE_REPORT_RECIPIENTS, SHOWCASE_REPORT_FROM. The HTML + PDF artefact has still been produced."` and exits 0. YAML validates.
