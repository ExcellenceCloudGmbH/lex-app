**`LEX_TASK_RECOVERY_ENABLED` default flipped `true` → `false` — a stuck `IN_PROGRESS` calculation resets on server restart again.** Follow-up to Session 89's Report 1/2 work: the developer restarted the local server and a calc was still `IN_PROGRESS`, expecting the restart to reset it. Root cause is the liveness-aware startup sweep (`process_admin.utils.model_registration._handle_calculation_model_reset`, introduced 2026-06-08): it no longer blind-aborts every stuck `IN_PROGRESS` row on boot — it **skips** rows a *tracked* recovery task owns (`supervisor.tracked_calculation_record_ids()`, which reads the Redis `index` set and deliberately ignores heartbeat liveness), trusting a recovery-supervisor pod (`celery worker -B -Q recovery`) to requeue/resume them. A crashed calc's task_id lingers in Redis (payload TTL 24h) across the restart, so the sweep skips it — but locally (and in any deploy that never provisioned the supervisor pod) nothing finishes it, orphaning the row `IN_PROGRESS` forever. Per the developer's decision ("set it to outright false"), the master switch now defaults **OFF** (`os.getenv("LEX_TASK_RECOVERY_ENABLED", "false")`), so `tracked_calculation_record_ids()` returns empty and the sweep reverts to its original blind-abort behaviour. Deployments running the supervisor opt back in explicitly (the `recovery-supervisor-deployment.yaml` manifest already sets `LEX_TASK_RECOVERY_ENABLED=true`; the shared instance-config does not — which is exactly why worker/web pods previously relied on the old `true` default). **Nested-calculation safety (explicitly requested — "calculation can dispatch calculations"):** verified the recovery flag gates ONLY the registry/heartbeat/supervisor + the sweep skip-set, never the dispatch path — the only calc-adjacent consumer is `celery.py:318` (supervisor import, internally gated, no-ops when off), and nested cluster-cancellation is gated on a SEPARATE flag (`LEX_CLUSTER_CANCEL_ENABLED`). A calculation that dispatches calculations is unaffected: 7j (three-level matrix), 7q, 8ab all pass.
