**Sub-cluster 8v landed — cluster-wide cascade cancellation via a best-effort Redis cancel index.** Root cause of the dangling-worker bug (reported after the PR #586 worker self-termination work): `CalculationModel.cancel()` could only revoke task_ids it found in `ActiveCalculationStateStore`, which is deliberately **per-process in-memory**. When a calculation tree fans children out across KEDA worker pods, those child task_ids live in other pods' memory — the root pod's `cancel()` never saw them, so Abort flipped the root to CANCELLED while children on other pods kept executing. **Fix (designed brainstorming→spec→plan, executed subagent-driven):** a new `lex/core/cancellation/cluster_cancel_index.py` keeps a best-effort Redis HASH tree keyed by `calculation_id` (`register_task` / `unregister_task` / `get_tree` / `mark_cancelled` / `is_cancelled`), written through at the existing `ActiveCalculationStateStore.set_task_id` (register) and `clear` (unregister) chokepoints — outside the store lock, wrapped in try/except so the index can never break tracking. `cancel()` now unions the in-memory descendants with `get_tree(calculation_id)` and revokes every cluster-discovered task (`revoke(terminate=True, signal="SIGTERM")`), and `mark_cancelled()` drops a `calculation_id`-keyed cooperative marker that `calc_and_save` checks at task start and self-aborts on (raising `CalculationCancelled`) — the non-relied-upon net for the late-booting-pod / discovery-gap case (signal-revoke is the primary kill; the marker guarantees correctness). Every Redis op degrades silently to a full no-op when there is no client, `CELERY_ACTIVE` is off, or `LEX_CLUSTER_CANCEL_ENABLED=false`; tree/marker TTLs are configurable via `LEX_CLUSTER_CANCEL_TREE_TTL_SECONDS` (default 4 h) / `LEX_CLUSTER_CANCEL_MARKER_TTL_SECONDS` (default 1 h). Broker queue-purge of still-pending tasks is documented as a deferred, flag-gated efficiency optimisation (correctness already guaranteed by revoke + marker). **Cluster 8v opened** (next-free letter after 8u; 8.78 picks up after the cluster max at 8.77): 8.78–8.82 index ops against a mocked Redis client; 8.83–8.84 disabled-config no-ops; 8.85–8.86 store write-through; **8.87 the integration surface** — `cancel()` revokes a child registered *only* in the Redis index (i.e. on another pod), driven E2E through `E2ETestCase` (`e2e_models=[CelerySyncCalc]`, `e2e_unpatch={"mark_in_progress"}`, schema-editor table creation matching `test_7n_cancellation.py`); 8.88–8.89 the cooperative marker self-abort.
