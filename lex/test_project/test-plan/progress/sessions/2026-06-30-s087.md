**Clusters 12i + 10o landed — Phase 1 backend foundations of the frontend/AG-Grid redesign: non-breaking FK display labels + per-field format metadata.** Part of the larger redesign (spec `docs/superpowers/specs/2026-06-30-lex-frontend-aggrid-redesign-design.md`, plan `docs/superpowers/plans/2026-06-30-lex-frontend-aggrid-redesign-phase1-backend.md`). The redesign wants FK cells to show a human label (not a raw PK) with a hover-preview card, and numeric columns to render with currency/percent/decimals — all without changing any existing serializer or `/fields/` output for models that don't opt in (the **non-breaking prime directive**). Two opt-in class attributes were added to `LexModel` (`lex_fk_label_field`, `lex_field_formats`) and consumed in two layers: **(a) serializer layer** — a new `_FkLabelInjectionMixin` emits a sibling `"<fk>_label"` string next to every FK primary key (FK value itself stays the PK), applied to BOTH `RestApiModelSerializerTemplate` and the `_wrap_custom_serializer` path so custom `api_serializers` also get labels; the mixin respects deny-all ({} stays {}) and never overwrites an explicit label, and composes correctly with the `pk_is_id` post-pass via MRO. Helper `resolve_fk_label` reads the target's `lex_fk_label_field`, falling back to `str(obj)`. **(b) `/fields/` layer** — `create_field_info` FK branch (guarded by the existing exact `ftype == ForeignKey` identity check — an earlier `isinstance` widening was reverted to avoid pulling `OneToOneField` subclasses into the FK branch, preserving non-breaking semantics) now adds `fk_label_field` + `fk_preview`; new helper `_target_has_preview_serializer` reports whether the target registers a `preview` serializer; `Fields.get` attaches `info["format"]` only for columns declared in `lex_field_formats` (undeclared columns carry no `format` key). FK-hint tests drive `create_field_info` with REAL Django FK fields (mirroring cluster 10e's `model._meta.get_field(...)`) rather than `MagicMock(spec=ForeignKey)`, so the production identity check is exercised exactly as it runs; two scoped test models added (`SchemaLabeledFKTarget` declaring both opt-in attrs + `SchemaLabeledItem` with a FK to it).
