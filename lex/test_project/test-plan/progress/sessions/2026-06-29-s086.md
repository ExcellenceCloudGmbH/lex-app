**Cluster 7q landed — nested calculation fan-out now dispatches to Celery by default from inside a worker; the `is_celery_worker_process()` inline guard is gone.** Diagnosed a production symptom: `InvestmentPosting` (65 568 models, 50 clusters) ran *synchronously* instead of dispatching. Root cause: a worker-detection guard (introduced commit `40d17b3`, Melih Sünbül, 2026-03-29) made nested fan-out **opt-in** — a calc already running inside a Celery worker collapsed its nested work to an inline sync run unless the caller opened an explicit `WaitForTasks`/`FireAndForget` scope, silently serialising a 65k-row combinatorial calc onto one worker slot. Per the user's decision ("change it to default without doing any fancy logic, don't worry about blocking"), the guard was removed from **both** dispatch paths: (1) `lex/core/mixins/CalculatedModelMixin.py` `_dispatch_model_processing` now fans out to `CeleryTaskDispatcher` whenever `CELERY_ACTIVE` + `cls.calculate.delay` exist (the dispatcher opens its own `WaitForTasks` when no scope is active, so the parent still blocks on its children); (2) `lex/core/models/CalculationModel.py` `calculate_hook` now always dispatches — reusing an outer async context when present, otherwise opening its own `WaitForTasks` and blocking on the child `result.get()` — instead of falling back to `execute_calculation_sync()`. `execute_calculation_sync()` is retained (no longer auto-called in this branch); `is_celery_worker_process()` is retained for diagnostics only. **Cluster 7q** (next free letter after 7p; 7.196 picks up after cluster max 7.195), Type E: 7.196 inside-worker no-context ⇒ mixin dispatches (not sync); 7.197 inside-worker + WaitForTasks ⇒ dispatches; 7.198 inside-worker + FireAndForget ⇒ dispatches; 7.199 CalculationModel no-context ⇒ own WaitForTasks dispatches + blocks; 7.200 outer WaitForTasks ⇒ child drained on scope exit (not before); 7.201 FireAndForget ⇒ dispatches, never blocks. Test-helper subtlety captured in-file: explicit `WaitForTasks()`/`FireAndForget()` must be constructed **inside** the `_celery_is_active=True` patch, else they build inert (`_active=False`) scopes that never register on the contextvar stack.
