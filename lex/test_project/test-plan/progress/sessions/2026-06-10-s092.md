First try was a live `kubectl exec` from IC into the customer's `django-backend` container to read `importlib.metadata.version('lex-app')` — blocked by RBAC (`pods/exec` is essentially "shell into any customer pod" and operations declined to grant it). Solution: the running customer pod is authoritative for its own `lex._version.__version__` and pushes it to IC over the **already-existing instance→IC HTTP channel** (env-injected `DOMAIN_BASE` + `LEX_API_KEY`, header `Authorization: Api-Key <key>`, same shape `lex.api.views.lex_api.LexAPI.send_email` already uses; no new credentials, no new cluster RBAC, no public exposure on the customer instance). **Source (new file `lex/lex_app/report_lex_app_version.py`):** `report_lex_app_version_to_ic(force=False)` schedules a **daemon** background thread targeting `_do_report` so startup cannot be blocked even if IC is hung or paused; a module-level latch + `threading.Lock` makes it once-per-process so multiple `AppConfig.ready` invocations (workers, replicas, restarts) do not flood IC; `force=True` is the documented test-only escape so cluster tests can drive the push path twice without leaking the latch. Three env vars (`DEPLOYMENT_ENVIRONMENT`, `DOMAIN_BASE`, `LEX_API_KEY`) gate the whole thing — local dev / CI / pytest runs never accidentally ping production IC. `_do_report` POSTs `{"version": __version__}` to `https://{DOMAIN_BASE}/api/report_lex_app_version/` with a 10-second timeout and **swallows every failure path** (network exception logged at INFO, non-200 response logged at INFO) so a broken or unreachable IC can never crash the customer pod's startup; the worst case is that IC keeps the previously-known version and the UI renders `Unknown`. Hooked into `LexAppConfig.ready` (`lex/lex_app/apps.py`) so the push fires on every server-process startup, wrapped in `try/except` for belt-and-braces protection. Backwards-compatible by design: customer instances running older lex-app versions (without this module) simply do not push and IC keeps `lex_app_version=""` → UI shows `Unknown`. **Cluster 1u** (next-free letter after 1t; 1.171 picks up after the cluster max at 1.170): 1.171 not-deployed env skips the push entirely (no thread started); 1.172 deployed env first call schedules a daemon thread targeting `_do_report`; 1.173 second call without `force=True` is guarded by the once-per-process latch; 1.174 `force=True` bypasses the latch (single documented escape); 1.175 `_do_report` POSTs the exact URL + `Authorization: Api-Key <key>` header + `{"version": <v>}` body that IC's `ReportLexAppVersion` view expects (drift here lands as 401/404 silently); 1.176 a `requests.RequestException` from the POST is swallowed without raising; 1.177 a non-200 response is swallowed without raising.
