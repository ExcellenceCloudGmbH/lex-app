# LEX Design System tokens — vendored Python module

Completed **Batch 1z** so the freshness-gate CI added by PR #686 has a paired
regression test covering what the vendored token file must guarantee to consumers.

`lex/lex_app/design_system/lex_tokens.py` is generated by
`@excellencecloudgmbh/lex-tokens` and copied verbatim (the Streamlit host cannot
reach the private GitHub Packages registry).  The tests pin:

- the module is importable without error
- all top-level shorthand constants (NAVY, TEAL, ERROR, …) are non-empty strings
- `TOKENS` exposes both `"light"` and `"dark"` modes with the standard structural
  sections (`color`, `radius`, `spacing`, `gradient`, `fontFamily`, …)
- the Phase 8 mandatory ERROR value `#d32f2f` is present in both modes
- the Phase 8 `onWarning` text role exists and is non-empty in both modes
- the top-level `ERROR` shorthand alias matches `TOKENS['light']['color']['status']['error']`
- both modes share the same top-level section keys (parity regression gate)
