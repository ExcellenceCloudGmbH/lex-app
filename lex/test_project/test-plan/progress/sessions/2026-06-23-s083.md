**Sub-cluster 3f landed — opt-in lean `_initial_state` removes the *last* full-field snapshot from the v1→v2 per-row footprint, without weakening any hook.** After 3e freed `_pre_validation_snapshot`, the remaining ~2.17× floor is django-lifecycle's `_initial_state` — a second full copy of every field, set in `__init__` and re-captured after each save (`ModelState.from_instance` = `__dict__.copy()`), powering `has_changed` / `initial_value` and the conditional-hook forms. v1 plain `Model`s had none of it. The framework's *only* dependency on it is `update_edited_at`'s `has_changed('edited_at')`; every other consumer is a user-declared `@hook(when=/when_any=/condition=)` clause whose field names are statically discoverable. **Fix (default ON, opt-out):** new `LexModel.lex_lean_initial_state` flag (defaulted to `True` after confirming via static analysis that the framework's *only* `_initial_state` reader is `has_changed('edited_at')`, which is always tracked, and that no framework code computes field-level diffs from the snapshot) narrows the retained snapshot to `edited_at` + every field named in this class's hook clauses (walks `_potentially_hooked_methods()` → `_hooked` HookConfigs: `when`, `when_any`, and the `condition=` object tree incl. chained `&`/`|`, via `field_name`) + `lex_initial_state_extra_fields` (escape hatch for imperative `self.has_changed('x')`). Built by filtering the full snapshot so stored values are byte-for-byte identical and unknown candidate keys drop harmlessly (over-include FK head + `_id` attname, never under-include). Covers all three library assignment sites: `__init__`, the `transaction.on_commit` re-baseline (`_reset_initial_state`), and `refresh_from_db`.
