**Sub-cluster 8h landed — Celery eager-mode end-to-end (broker-free real dispatch).** User flagged that the `CELERY_ACTIVE=true` production code paths in `celery_tasks.py`, `CeleryTaskDispatcher`, and `CalculatedModelMixin._dispatch_model_processing` were **never exercised end-to-end** — 8g had proven the routing logic with `.delay` patched to a MagicMock but nothing ever ran the real `.delay()` → `@lex_shared_task` wrapper → task body → `CallbackTask.on_success`/`on_failure` sequence, and 7h had mocked `CeleryTaskDispatcher.dispatch_calculation_groups` rather than running it. This sub-cluster closes that gap without Redis / RabbitMQ / a running worker by using **Celery's own test harness** — `app.conf.task_always_eager=True` + `task_eager_propagates` — which makes `.delay(...)` run the task body **inline in the calling thread** and return a real `EagerResult`. The broker is faked by Celery itself, not by us; every other moving part (the `@lex_shared_task` wrapper, the `CallbackTask` base class, the `task_postrun` signal, the ORM writes, the audit seam) is the real production code. New `test_8h_eager_end_to_end.py` with a shared `_celery_eager(propagate=True)` context manager that flips the three knobs and restores them on exit.
