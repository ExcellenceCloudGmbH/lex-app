**Added explicit `CalculationModel.CANCELLED` state for user-initiated cancellation — kept `ABORTED` as the distinct startup-recovery state.** Original intent of this session was a full ABORTED→CANCELLED rename, but the user clarified that the two states answer different audit questions and must stay separate: **ABORTED** is the framework-side recovery state (a row found stuck in IN_PROGRESS at startup is flipped to ABORTED by `process_admin.utils.model_registration._handle_calculation_model_reset` because the worker crashed); **CANCELLED** is the new state set when a human operator deliberately stops a running calc via `CalculationModel.cancel()` (or a cooperative `CalculationCancelled` exception raised from inside `calculate()`). Both are non-success terminal states and both audit as `failure`, but the compliance trail now distinguishes "did an operator stop this?" from "did the framework give up on a crashed worker's row?".
