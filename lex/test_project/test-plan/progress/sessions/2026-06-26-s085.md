**Sub-cluster 8aa landed — the post-task warm shutdown now honours the `LEX_WORKER_IDLE_SHUTDOWN_ENABLED` master switch, fixing the recovery-beat crash-loop.** Field follow-up to Session 84: after the timezone fix, the embedded-beat recovery pod (`celery_beat_recovery.yaml`, runs `celery worker -B`) booted, the schedule became due, and `sweep_dead_workers` fired and succeeded — then the pod immediately `worker: Warm shutdown` → `beat: Shutting down` and crash-looped. Root cause in `lex/lex_app/celery.py`: three worker self-termination paths exist (`task_postrun` post-task shutdown, `task_revoked` cancel fast-path, and the `worker_ready` idle watchdog). The revoke path and the watchdog both gate on `_idle_shutdown_enabled()`, but the `task_postrun` handler `shutdown_worker_after_task_completion` only checked `_is_non_local_deployment_target()` and `task is None` — it was **missing** the `_idle_shutdown_enabled()` guard. So the recovery pod's `LEX_WORKER_IDLE_SHUTDOWN_ENABLED=false` (set precisely because that pod is idle-by-design between sweeps and must keep beat alive) did not actually stop the post-task warm shutdown; the pod self-terminated after its first sweep. The chart comment (`celery_beat_recovery.yaml:81-90`) already promised the flag disables "both the watchdog and post-task warm shutdown" — the code now matches that promise. **Fix:** add `or not _idle_shutdown_enabled()` to the early-return guard in `shutdown_worker_after_task_completion`, identical to the other two paths. **Cluster 8aa** (8y and 8z were both already taken — 8y by the embedded-beat recovery driver, 8z by the initial-data calc executor — so this batch takes the next free letter past z; 8.125 picks up after cluster max 8.124), Type U: 8.125 master switch off ⇒ no post-task shutdown broadcast (the recovery-beat case — the bug); 8.126 switch on + non-local ⇒ broadcast still fires to the completing worker with `completed_task_id` excluded (KEDA scale-to-zero path unaffected); 8.127 local deployment target ⇒ never broadcasts; 8.128 `task=None` ⇒ safe no-op. This handler previously had **no** test covering the disabled-flag path — that gap is what let the bug through. Source: `lex/lex_app/celery.py`.
